# IDD 子 skill · Step 8 · 审查

骨架：`skills/workflow-steps/step-review/SKILL.md`。领域规则：`skills/document-types/ItemDefinitionDocument/SKILL.md`。

## 本步目的要点

- 对照 template、checklist、证据审查 `draft/full_draft.md`。
- **IDD 审查维度**：
  - Clause 5 完备性（功能、边界、接口、环境、工况、假设、误用）
  - 接口信号方向是否明确
  - 边界 In/Out 是否双向覆盖
  - 证据 tier 与 citation 是否匹配
  - **无 HARA 危害/评级内容**
  - sample 未当事实
- 产出 `review/*`（template/checklist/evidence/final review）。

## IDD 方法论（本步定位）

本步对应 **阶段 6：审查与验证** 中的 **内容审查** 环节。

### 阶段 6 · 内容审查（本步执行，同行/系统工程师视角）

1. **Clause 5 检查项是否覆盖**（功能、边界、接口、环境、工况、假设、误用）。
2. **功能是否与 SyRS 一致**。
3. **边界是否与架构一致**（In/Out 双向）。
4. **接口方向是否完整**（输入/输出/双向 + 对端）。
5. **误用是否单独成节**或有 open 说明。
6. **假设是否显式列出**，未与误用混写。

### 成功标准（审查视角）

| 检查项 | 通过条件 |
|---|---|
| 功能 F-xx | 有来源或显式 open |
| 系统边界 | In/Out 双向；与架构一致 |
| 外部接口 | 含方向与对端 |
| 运行环境 | 有来源或 open |
| 运行工况 | 事实性描述，无 E 评级 |
| 假设与依赖 | 显式列出 |
| 合理可预见误用 | 单独成节或有 open |
| 全文 | 无危害分析结论，不与 HARA 混写 |

审查结论为 **review-ready 评估**，**不等于** ISO 26262 合规认证或 Item 定义正式批准。

### 内容审查 Review 要点（本步执行）

| 维度 | Review 要点 |
|---|---|
| 与需求一致 | F-xx 是否与 SyRS/SRS 一致；有无无来源的功能 |
| 与架构一致 | 边界是否与系统架构/子系统划分一致 |
| 接口完整性 | IF-xx 是否有名称、类型、**方向**、对端、信号/机械说明 |
| 边界双向性 | 是否同时有 In scope 和 Out of scope |
| 误用独立性 | 误用是否单独成节，未藏在假设或环境节里 |
| 工况事实性 | OS-xx 是否为场景事实描述，未做 E 评级或危害推断 |
| 证据匹配 | critical claim 是否有 T0/T1 证据；citation 是否可追溯 |
| 缺口诚实性 | 缺证据处是否保留 `NEEDS_USER_CONFIRMATION` / `[PENDING]` |
| 文档边界 | 审查结论是 review-ready 评估，**不是**合规认证或正式批准 |

### P0 失效项（本步重点抓）

| 失效 | 后果 |
|---|---|
| 样例 IDD 功能/边界被当事实 | HARA 基线错误 |
| IDD 中含 hazard / ASIL / SG | 文档类型混淆 |
| 接口无方向且标为已确认 | 后续接口/故障传播分析困难 |
| 误用节缺失且无 open | 不符合 §5.4.4 b |
| 含「已批准」「已合规」等措辞 | 越权结论 |
| 缺材料静默填值（无 EVD 无 open） | 不可追溯 |

### P1 失效项（也应修）

- 边界只有 In 没有 Out → HARA 范围膨胀
- 假设隐式而非显式
- 引用文档无版本号
- 接口方向材料缺失但未登记 gap

### 一句话归纳

**Checklist 核心**：Clause 5 七类内容（功能、边界、接口、环境、工况、假设、误用）齐全或有 open；接口有方向；边界 In/Out 双向；误用独立成节；全文无 HARA 内容。  
**Review 核心**：内容与 SyRS/架构一致、证据 tier 合规、sample 未当事实、缺口显式、措辞保守、结论不越权批准。

## Clause 5 Checklist（审查勾选）

- [ ] §5.4.1 Item 标识（名称、版本、变型）已覆盖或可追踪 open
- [ ] §5.4.2 功能信息已覆盖或可追踪 open
- [ ] §5.4.3 系统边界清晰（In/Out 双向）
- [ ] §5.4.3 外部接口含**方向**与对端
- [ ] §5.4.4 运行环境与约束有来源或 open
- [ ] 运行工况与模式有事实性描述（无危害结论）
- [ ] §5.4.4 假设与依赖显式列出
- [ ] §5.4.4 b 合理可预见误用单独成节或有 open 说明
- [ ] 无 hazard / ASIL / Safety Goal 内容渗入

## 常见错误（本步重点抓）

| 错误 | 后果 | 级别 |
|---|---|---|
| 把样例 IDD 的功能/边界照抄 | 事实错误，HARA 基线错误 | P0 |
| IDD 里写 hazard / ASIL | 文档类型混淆 | P0 |
| 接口无方向 | 后续分析困难 | P0 |
| 边界只有 In 没有 Out | HARA 范围失控 | P1 |
| 误用缺失或藏在假设里 | §5.4.4 b 不满足 | P0 |
| 写「定义已批准」「已合规」 | 越权结论 | P0 |

## A1 / A2 / B

**A1**：checklist 项有结论；P0（sample 当事实、HARA 泄漏、接口无方向、误用缺失）无遗漏。  
**A2**：按 findings 修订草稿计划（交 Step 10）。
**B**：review 与 IDD 边界一致，非合规批准。
