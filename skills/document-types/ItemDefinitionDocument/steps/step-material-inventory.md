# IDD 子 skill · Step 2 · 材料清单

骨架：`skills/workflow-steps/step-material-inventory/SKILL.md`。领域规则：`skills/document-types/ItemDefinitionDocument/SKILL.md`。

## 本步目的要点

- 解析每份材料，产出 `inputs/input_inventory.json`。
- 登记 `parse_status`、`role`、`is_fact_source`。
- **source** 解析摘要须覆盖：功能列表、边界、接口（含方向）、环境约束、工况、假设、误用线索。
- **sample** 解析结果仅入 `style_hint` / `style_example`，**禁止**写入 F-xx/IF-xx/边界事实字段。
- 失败/缺失如实标记，不静默吞掉。

## IDD 方法论（本步定位）

本步对应 **阶段 1：材料消化** 的第一环——在建立可检索索引（Step 3）之前，对每份输入做结构化解析与摘要。

### 阶段 1 · 材料消化（本步执行）

1. 解析 SyRS、架构、接口规范等，为后续索引准备 **可提取文本**。
2. 从 **source** 材料中提取 **候选 F-xx、IF-xx、边界条目**，仅作候选，**尚未定稿**。
3. **样例 IDD** 只提取 **表头、章节粒度**，不复制具体功能/边界内容。

### 输入材料解析重点（与 Clause 5 对齐）

| 类别 | 典型文档 | 本步须提取的摘要 |
|---|---|---|
| 需求 | SyRS、SRS、功能需求 | F-xx 候选、功能描述片段 |
| 架构 | 系统架构、子系统划分 | In/Out scope 候选 |
| 接口 | 接口规范、CAN/LIN 矩阵 | IF 名称、类型、**方向**、对端 |
| 场景 | ODD、用例、场景说明 | 工况类型、模式、环境 |
| 约束 | 环境规范、安装条件 | 温度/电压/速度等参数 |
| 假设 | 安全假设、依赖清单 | 假设条目、外部依赖 |
| 方法学 | ISO 26262-3 Clause 5 | 不提取项目事实 |
| 样例 | 历史 IDD | **仅**章节层级、表头形状 |

**原则**：样例文档可以提供「怎么写」的结构线索，不能替代本项目 SyRS/架构/接口中的「写什么」。

## 本步定位

为 Step 3 文档目录索引提供可索引文本；**不做 Item 专业判断**，不确认功能完整性或边界最终性。

### 各 role 提取重点

| role | 须提取（摘要级） | 禁止 |
|---|---|---|
| source（需求/架构） | F-xx 候选、In/Out scope、IF 名称与方向、速度/温度约束 | 将候选标为「已确认」 |
| source（ODD） | 工况类型、模式、环境 | 做 E 评级或危害推断 |
| source（假设） | 假设条目、外部依赖 | 与误用混写 |
| template | 强制章、F/IF/边界表列定义 | 提取具体功能值 |
| sample | 章节层级、表头 | **不**提取具体功能/边界值 |
| reference | 方法学章节标题 | 当作项目事实 |

### 成功标准（本步视角）

- 每份材料有明确 `parse_status`（成功/失败/部分）。
- source 摘要覆盖功能、边界、接口、环境、工况、假设、误用 **七大主题线索**（可部分为空但须标 gap）。
- sample 解析结果 **未流入** 任何事实字段。

## 本步 Review / Checklist 要点

本步产出将在 Step 10 审查「sample 是否当事实」、Step 11 验证 VC-2 tier 合规时被回溯。

### 与本步相关的 Clause 5 预备检查

- [ ] source 摘要覆盖功能（§5.4.2）、边界（§5.4.3）、接口含方向（§5.4.3）
- [ ] source 摘要覆盖环境（§5.4.4）、工况、假设（§5.4.4）、误用线索（§5.4.4 b）
- [ ] sample 解析结果仅入 `style_hint`，未写入 F-xx/IF-xx/边界事实字段
- [ ] 每份材料有 `parse_status`；失败项未静默跳过

### 本步 Review 要点

| 维度 | 检查项 | 级别 |
|---|---|---|
| 事实来源分离 | sample 未流入事实字段 | P0 |
| 接口方向 | IF 摘要含方向信息或 gap | P0 |
| 七大主题 | 功能/边界/接口/环境/工况/假设/误用线索已尝试提取 | P1 |
| 候选 vs 确认 | 候选 F-xx/边界未标为 confirmed | P1 |
| 解析完整性 | 无静默 parse 失败 | P0 |

### 本步自检（交付前）

- [ ] `input_inventory.json` 中 sample 条目无 F-xx/边界具体值
- [ ] 接口摘要列含方向或对端，或已标 gap
- [ ] 误用线索与假设条目未混写在同一事实字段

## 常见错误（本步重点防）

| 错误 | 后果 | 级别 |
|---|---|---|
| 把 sample IDD 的功能/边界照抄进 inventory 事实字段 | 事实来源违规，HARA 基线错误 | P0 |
| 接口摘要无方向 | 后续 IF-xx 表缺方向列 | P0 |
| 解析失败静默跳过 | 不可追溯 | P0 |
| 将候选 F-xx 标为 confirmed | 越权确认，违反保守原则 | P1 |

## A1 / A2 / B

**A1**：parse_status 齐全；sample 未流入事实字段；source 七大主题线索已尝试提取。  
**A2**：重解析失败项、补摘要。  
**B**：核对 source 摘要是否支撑后续 SEC-FUNC/BOUNDARY/IF/ENV/OPS/ASSUMP/MISUSE。
