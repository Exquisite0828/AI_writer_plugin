# Test Reporting Methodology Reference

## Purpose

This reference describes general test report structure and terminology. It is not project-specific result evidence.

## General Guidance

- Test reports should identify the system under test, version, scope, environment, executed cases, results, known defects, coverage limits, and open issues.
- PASS, FAIL, BLOCKED, and NOT_RUN are execution statuses that should be tied to recorded evidence.
- Release readiness is a review decision and should not be inferred from a sample report or methodology reference.

## Boundary

This reference must not prove project-specific test results, pass/fail status, defect state, coverage sufficiency, or release readiness.
