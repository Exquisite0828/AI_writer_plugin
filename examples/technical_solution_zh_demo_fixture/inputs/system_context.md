# 系统上下文

目标系统是一个内部功能开关灰度发布服务，用于让后端服务在发布新功能时按服务、环境和用户分组逐步放量。

现有系统已经提供一个 REST API，后端服务会在请求处理过程中读取功能开关状态。现有后端客户端 SDK 依赖这个 API 的字段名和响应结构。

当前已知组件：

- API 服务
- 配置存储
- 后端客户端 SDK
- 审计日志导出器

当前部署环境：

- 服务运行在公司内部 Kubernetes 平台。
- 配置变更需要写入审计日志。
- 现有后端客户端不能在第一阶段被强制升级。

当前约束：

- 必须保持现有 REST API 兼容。
- 必须保留功能开关变更的审计记录。
- 上线方案必须包含回滚路径。

当前待确认事项：

- 最终架构决策尚未由架构评审确认。
- 安全边界尚未由安全负责人确认。
- 性能目标尚未由服务负责人确认。
- 上线风险接受尚未由项目负责人确认。
