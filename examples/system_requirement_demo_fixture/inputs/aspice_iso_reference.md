# ASPICE SYS.2 and ISO 26262 Interface Reference

Document status: methodology reference only.

## ASPICE SYS.2 Method Reference

For this demo, System Requirement writing should preserve the following process intent:

- Analyze stakeholder requirements and identify system-level implications.
- Specify system requirements with unique identifiers and verifiable wording.
- Analyze requirements for consistency, feasibility, and testability.
- Maintain traceability between stakeholder requirements and system requirements.
- Keep open items visible when stakeholder confirmation is missing.

## ISO 26262 Interface Reference

For this demo, SyRS provides upstream source material for later functional safety work:

- Item Definition can use SyRS function, boundary, interface, and operating constraint information.
- HARA and FSR are separate downstream activities.
- SyRS should not create hazards, ASIL ratings, Safety Goals, or Technical Safety Requirements.

This reference does not prove any project-specific EPS requirement.
