# System Requirement Review Checklist

## ASPICE SYS.2 Alignment

- Stakeholder requirements are identified and summarized.
- System requirements are structured, uniquely identified, and verifiable.
- Each system requirement has upstream traceability or an explicit open item.
- The traceability matrix supports upstream-to-SyRS and SyRS-to-upstream review.
- Open communication and confirmation items are visible.

## System Requirement Quality

- Each requirement uses shall / 应 language.
- Each requirement is single-purpose and testable.
- Interface requirements include direction and counterpart.
- Performance and environmental limits include units and source support.
- Verification methods are marked as candidates unless confirmed by source or HITL.

## Functional Safety Boundary

- SyRS does not introduce HARA conclusions, ASIL ratings, or Safety Goals.
- Safety-related content only references provided FSR / SG source material.
- Final report is review-ready and is not an approval or compliance certification.

## With-Reference Boundary

- Reference SyRS documents may guide structure only.
- Reference SyRS content must not support SYS-F, SYS-IF, performance limits, or diagnostic facts.
- Delta analysis is required when a reference SyRS is supplied.
