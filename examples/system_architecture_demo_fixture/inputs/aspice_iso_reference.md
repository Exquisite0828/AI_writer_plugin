# ASPICE SYS.3 and ISO 26262 Interface Reference

Document status: methodology reference only.

## ASPICE SYS.3 Method Reference

For this demo, System Architecture writing should preserve the following process intent:

- Analyze upstream system requirements and derive logical and physical architecture views.
- Define architecture elements, interfaces, and allocation relationships with unique identifiers.
- Analyze architecture for consistency with requirements, platform constraints, and feasibility.
- Maintain traceability between system requirements and architecture elements.
- Keep open items visible when stakeholder or platform confirmation is missing.

## ISO 26262 Interface Reference

For this demo, System Architecture provides upstream structure for later functional safety and software work:

- Item Definition and HARA can use architecture boundary and interface information from upstream sources.
- FSR and TSC are separate downstream activities; System Architecture does not create them.
- System Architecture should not create hazards, ASIL ratings, Safety Goals, or Technical Safety Requirements.

This reference does not prove any project-specific EPS architecture element, allocation, or interface.
