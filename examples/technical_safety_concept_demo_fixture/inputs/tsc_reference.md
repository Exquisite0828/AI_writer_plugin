# Technical Safety Concept Writing Reference

This reference describes general writing quality for technical safety concepts.
It is not project evidence.

A technical safety requirement should be technically implementable and verifiable, for example a detection time bound, a redundancy strategy, a diagnostic cycle limit, or a safe shutdown path. It should not merely restate the functional requirement.
A technical safety requirement is normally linked to an upstream functional safety requirement, a safety goal, an architecture allocation, and a verification approach.
Fault tolerance time interval (FTTI), fault detection time interval (FDTI), and fault handling time interval (FHTI) should be expressed explicitly, preferably in a table.

General methodology references may help reviewers check structure and wording quality, but they cannot prove project-specific technical safety requirements, mechanisms, ASIL inheritance or decomposition, allocation, verification status, or final acceptance.

This reference must not be cited as fact support for this project's TSC content.
